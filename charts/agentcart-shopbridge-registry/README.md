# AgentCart ShopBridge registry chart

This chart serves a small, read-only merchant discovery plane from declarative
ShopBridge registry records. It deliberately does not deploy the full AgentCart
buyer gateway, accept merchant submissions, create a database, or claim that an
onchain registry exists when no contract address has been configured.

The public surface is limited to:

- `/` and `/registry` — human-readable pilot landing page;
- `/v1/registry` — registry metadata plus entries;
- `/v1/registry/records` — the agent-facing `entries[]` feed;
- `/v1/registry/health` — deployment/feed status;
- `/v1/registry/transparency` — curation mode and update status;
- `/v1/registry/onchain` — explicit Ethereum mainnet and Tempo deployment status.

The ingress intentionally does not claim `/v2/`. A Kubernetes ingress
controller can therefore route the same host's more-specific `/v2/` path to an
OCI Distribution registry while routing the paths above to this service.

## Validate

```sh
bash scripts/check-shopbridge-registry-chart.sh
```

`values.pilot.yaml` contains only public records generated by the two public
AgentCart staging merchants. It is a reproducible demo overlay, not a Secret or
a template for private cluster topology.

## Install

Use a reviewed values file containing public merchant records and the exact
ingress source CIDRs observed in the target cluster:

```sh
helm upgrade --install shopbridge-registry \
  charts/agentcart-shopbridge-registry \
  --namespace merchant-registry \
  --create-namespace \
  --values /secure/operator/path/registry-values.yaml
```

If this chart shares a hostname with an existing OCI registry, install it in
the namespace that owns the TLS Secret named by `registry.tlsSecretName`.

`maintainer_curated` is the only supported submission mode in this pilot
chart. Merchant self-service, durable append-only transparency, and onchain
registration require a separate reviewed stateful registry service.
